## 2. 시나리오 (5~10줄)

* 이 프로그램은 사용자가 직접 방문하거나 가고 싶은 음식점 및 카페만을 검색하여, 자신만의 기준(0~5점, 1점 단위)으로 별점을 매기고 짧은 한줄평을 기록해 다중 폴더에 담아 관리하는 개인 맞춤형 지도 시스템입니다. 사용자가 폴더별로 지정한 고유 이모티콘(마커)이 지도 위에 직관적으로 표시되어, 나만의 테마 지도를 한눈에 파악할 수 있습니다. 또한, 하나의 맛집을 여러 폴더에 중복으로 넣을 수 있는 유연한 관리 시스템과 폴더 내 검색 기능을 지원하여, 텍스트 형태가 아닌 시각적으로 완성도 높은 나만의 커스텀 맛집 지도를 구축할 수 있도록 기획되었습니다.

3. 유연한 다중 폴더링 및 검색: 평가한 식당을 여러 테마 폴더에 동시 저장 가능. 폴더 내에서 가게 이름을 다시 검색하거나, 전체 맛집을 특정 폴더로 분류하는 양방향 탐색 지원

## 🟩 [2차 과제: V2.0] 입출력 + 리스트 + 조건문
### **✨2차 과제 내용:**

이번 과제는 1주차에서 기획한 '내 맘대로 폴더링 맵'의 기능인 식당 정보 입력 및 커스텀 별점 평가 시스템을 파이썬의 입출력, 리스트, 조건문을 활용해 구현하는 것입니다. 반복문(for/while)은 완전히 배제하였으며, 사용자로부터 식당 이름, 카테고리, 별점, 한줄평, 그리고 폴더명을 입력받아 하나의 리스트(List)에 저장합니다. 특히 입력된 데이터를 바탕으로 `if-elif-else` 다중 조건문을 통해 만족도 등급을 나누고, `match-case` 문법을 활용하여 상호명에 따라 식당과 카페 등의 카테고리를 자동 판별하는 지능형 분기 로직을 완성했습니다.
* `input()`으로 식당 정보를 입력받고 숫자로 필요한 값은 `int()`로 형변환.
* 식당 카테고리가 '음식점(FD6)' 또는 '카페(CE7)'인지 확인하는 중첩 if문 구조 적용 및 옷 가게 등 예외 처리.
* `match-case`를 사용하여 상호명을 입력하면 카테고리를 자동 판별하는 '모의 데이터(Mock data)' 패턴을 적용. (실제 서비스의 Map API 연동 논리를 과제 제약 내에서 시뮬레이션)
* 사용자가 직접 폴더명과 맵핑될 이모티콘 마커(💖, 🎧 등)를 모두 동적으로 입력받아 확장성 확보.
* 복합 논리 연산자(`and`, `or`, `==`)를 활용해 만점 평가와 특정 폴더가 결합된 경우 '✨ 완벽한 나만의 맛집! ✨'과 같은 특별 칭호 부여.
    
### **🤖 AI 파트너십 과정**

1. **내용 1: 상호명 기반 카테고리 자동 판별 및 커스텀 마커 동적 입력 로직 도출**
    * **프롬프트 요약:** "식당 코드를 직접 입력하는 대신 가게 이름을 치면 카테고리가 자동으로 인식되고, 폴더명에 쓸 이모티콘도 내가 직접 입력할 수 있게 만들려면 어떻게 해야 할까?"
    * **적용 내용:** 카테고리 자동 인식의 경우 수많은 데이터를 처리해야 하므로, 실무에서는 Map API를 연동하지만, 본 과제에서는 제한 조건(반복문 금지)에 맞추어 C언어의 'switch-case'와 대응되는 파이썬 'match-case' 문법을 도입해 '모의 데이터(Mock data)' 패턴을 구현하는 아이디어를 AI로부터 제안받았습니다. 또한 이모티콘 마커는 코드 내부에 하드코딩하는 대신 'input()'으로 동적 입력받도록 설계하여 '커스텀 맵'의 기획 의도를 극대화했습니다.
    
2. **내용 2: 음식점/카페 한정 필터링을 위한 중첩 조건문 설계**

    * **적용 내용:** 입력의 가장 첫 단계에서 `if category == "FD6" or category == "CE7":` 라는 복합 조건식을 사용하여 카테고리의 유효성을 1차적으로 검증했습니다. 그리고 조건이 참일 때만 내부 들여쓰기 공간(중첩 구조)에서 별점 평가 및 폴더링 로직이 실행되도록 설계하여 잘못된 데이터 입력 시 즉각 종료되게 만들었습니다.
    
### **🛠️ Troubleshooting & 기술 회고:**

1. **문제 1: 입력한 별점 숫자로 등급을 계산하려는데 발생한 에러 (TypeError)**
    * **원인:** `input()` 함수로 입력받은 별점(예: 5)이 겉보기엔 숫자라도 파이썬 내부에서는 문자열(str)로 취급되어, 크기 비교 연산(>= 등)을 할 때 오류가 발생했습니다.
    * **해결:** `int()` 함수를 사용하여 `rating = int(rating_str)`로 변수 타입을 강제로 정수형으로 바꾸어주는 '형변환'을 거친 후 조건문을 실행해 말끔하게 해결했습니다.
    
2. **문제 2: match-case 구문에서 다중 패턴 지정 시 발생한 문법 에러 (syntax Error)**
    * **원인:** `case "스타벅스' or "이디야":' 처럼 일반적인 if문에서 쓰던 'or' 키워드를 'match-case' 안에서 그대로 사용하려다가 문법 에러가 발생했습니다. 
    * **해결:** 파이썬의 'match-case' 문에서 여러 조건을 한 번에 묶을 때는 'or' 대신 '|'(파이프) 기호를 사용해야 한다는 점을 파악하고, 'case "스타벅스" | "이디야":' 형태로 수정하여 문법 오류를 해결했습니다.

## 🟨 [3차 과제: V3.0] 함수화 + 반복문 + 예외 처리
### **✨ 3차 과제 내용:**
이번 과제는 2차 과제 시스템을 함수(`def`)로 구조화하고, 반복문(`while/for`)을 도입해 여러 데이터를 누적 관리할 수 있도록 프로그램을 확장하는 것입니다.
* **사용자 메뉴 구성**: `while True` 무한 루프를 적용하여 장소 등록, 전체 조회, 통계 분석, 프로그램 종료를 관리하며, 사용자가 '종료'를 선택할 때만 `break`로 끝나도록 구현했습니다.
* **함수 정의 및 분리**: 메인 함수(`main()`)를 가독성 높게 구성하기 위해 핵심 로직을 5개의 개별 함수(`get_category`, `calculate_tier`, `register_place`, `show_places`, `analyze_places`)로 분리 정의했습니다.
* **매개변수와 반환값**: 상호명을 받아 카테고리를 리턴하는 `get_category()`와 별점을 받아 등급을 리턴하는 `calculate_tier()`를 설계하여 매개변수와 return 제어를 적용했습니다.
* **전역/지역 변수 관리**: 맛집 데이터를 저장하는 전역 리스트(`places_list`)와 총 개수 카운터(`total_registered`)를 구분하여 관리하며, 수정이 이루어지는 부분에 `global` 키워드를 사용해 상태 변화를 기록했습니다.
* **예외 처리**: 숫자가 아닌 값을 입력하더라도 에러가 발생하며 프로그램이 비정상 종료되지 않도록 `try-except`로 별점 입력을 예외 처리했습니다.

### **🤖 AI 파트너십 과정**
1. **내용 1: 단일 데이터 보관에서 무한 루프 & 다중 데이터 관리로의 확장**
    * **프롬프트 요약:** "기존에 장소 하나만 등록하고 끝나는 코드를, 사용자가 원할 때까지 계속 등록하고 조회도 하고 통계도 낼 수 있는 프로그램으로 바꾸고 싶어. 메뉴판도 나오게 해주고."
    * **적용 내용:** 메인 흐름을 `while True` 무한 루프와 `break` 조건으로 설계하고, 메뉴 구조를 구성하여 사용자가 원할 때 프로그램이 안전하게 종료되도록 하였습니다. 또한 전역 리스트인 `places_list`를 두어 복수의 장소 정보가 누적 보관될 수 있도록 데이터 영속성을 시뮬레이션하였습니다.
    
2. **내용 2: 기능 함수화 및 전역 변수 가시성 제어 (`global` 활용)**
    * **프롬프트 요약:** "기존 2차 과제의 코드들을 def로 쪼개야 하는데, 전체 등록된 장소 개수나 목록을 여러 함수에서 공유하고 변경하려면 어떻게 해야 해? 그리고 3개 이상 함수로 쪼개는 팁이 있을까?"
    * **적용 내용:** 기능에 따라 등록(`register_place`), 목록 출력(`show_places`), 통계 분석(`analyze_places`), 카테고리 자동판별(`get_category`), 등급 평가(`calculate_tier`)로 잘게 쪼개어 가독성을 높였습니다. 총 등록 개수(`total_registered`) 전역 변수를 `register_place` 내부에서 `global` 키워드로 변경하는 패턴을 적용하여 전역 변수와 지역 변수의 역할을 명확히 구분하였습니다.

### **🛠️ Troubleshooting & 기술 회고:**
1. **문제 1: 별점 정수 변환 시 숫자가 아닌 값 입력으로 인한 런타임 에러 (`ValueError`)**
    * **원인:** 사용자가 별점에 실수로 문자를 입력하거나 빈 칸으로 엔터를 누르면 `int()` 형변환 시 `ValueError`가 발생해 프로그램이 비정상적으로 종료되는 문제가 발생했습니다.
    * **해결:** `try-except` 예외 처리 블록을 적용하여 `ValueError` 발생 시 경고 메시지를 띄우고 메인 메뉴로 안전하게 복귀하도록 흐름을 제어함으로써 프로그램의 견고성(Robustness)을 크게 향상시켰습니다.
    
2. **문제 2: 다중 데이터 조회를 위한 리스트 내부 인덱싱 에러 (`IndexError`)**
    * **원인:** `places_list`에 저장된 데이터를 가져와 출력할 때 리스트의 요소 위치(인덱스)를 혼동하여 엉뚱한 값을 출력하거나 범위를 벗어나 `IndexError`가 나는 경우가 염려되었습니다.
    * **해결:** 각 장소 리스트의 인덱스 구조(`[식당명, 카테고리, 별점, 한줄평, 폴더명, 이모티콘, 등급, 특별칭호]`)를 주석으로 명시하고, 루프를 돌 때 `for` 문에서 파이썬의 **변수 언패킹(Unpacking)** 문법을 사용하여 `name, cat, rating, review, folder, emoji, tier, special = place` 형태로 직관적으로 분리하여 인덱스 에러를 원천 차단하고 가독성을 극대화했습니다.

    * **적용 내용:** 데이터 저장을 위한 `save_to_file()` 함수와 불러오기를 위한 `load_from_file()` 함수를 작성했습니다. 구분자는 데이터(한줄평) 내부에 쉼표(`,`)가 들어가는 상황을 대비해 탭(`\t`) 문자를 채택했습니다. 예외 처리는 `load_from_file()` 내에서 파일이 존재하지 않을 때 발생하는 `FileNotFoundError`를 예외 처리하여 프로그램이 부드럽게 초기 상태로 시작할 수 있도록 1차 차단했고, 데이터 정수 변환 오류(`ValueError`)와 파일 저장 실패(`IOError`)도 2차, 3차로 안전하게 제어했습니다.
    
### **🛠️ Troubleshooting & 기술 회고:**
1. **문제 1: 한줄평 속 쉼표(,) 입력 시 CSV 파싱 붕괴 문제**
     * **원인:** 데이터를 쉼표(`,`)로 구분하는 단순 CSV 포맷으로 파일 입출력을 기획하였으나, 사용자가 한줄평에 쉼표를 포함하는 순간(`리뷰: "진짜 최고, 내 최애 맛집!"`) 한줄평이 여러 필드로 쪼개어지면서 불러오기 시 `IndexError`나 데이터 유실이 발생하는 치명적인 취약점이 존재했습니다.
     * **해결:** 파일 저장 형식의 구분자를 쉼표 대신 탭 문자(`\t`)로 채택하는 **TSV(Tab-Separated Values)** 방식으로 구조를 전환하였습니다. 이를 통해 한줄평 내의 쉼표나 특수문자와 무관하게 모든 데이터 필드가 완벽하게 독립적으로 읽고 쓰여 문제를 해결했습니다.
  
  2. **문제 2: 최초 실행 시 저장 파일이 없어 발생하는 비정상 종료 (FileNotFoundError)**
     * **원인:** 프로그램 시작과 동시에 실행되는 `load_from_file()` 함수가 `my_places.txt` 파일을 읽어오려 하지만, 프로그램 최초 실행 시에는 파일이 없어 `FileNotFoundError`가 발생하고 비정상 종료되는 현상이 있었습니다.
     * **해결:** `with open()` 구문 전체를 `try-except FileNotFoundError:` 블록으로 감싸주어, 최초 기동 시 파일이 없어도 예외를 잡아낸 후 "기존 저장 파일이 없으니 새로운 지도를 생성한다"는 안내 메시지만 띄우고 안정적으로 프로그램이 시작되도록 조치했습니다.
